## Core Mechanics of Self‑Attention
Self‑attention lets each token attend to every other token in the same sequence. Input embeddings are linearly projected into **queries (Q)**, **keys (K)**, and **values (V)**. The attention score between token *i* and *j* is the scaled dot‑product \(\frac{Q_i K_j^T}{\sqrt{d_k}}\). Softmax across the scores yields a weight distribution, which is used to compute a weighted sum of the values, producing the output representation for each token.

## Edge Cases & Failure Modes
When sequences are very long, attention scores become noisy, leading to diffusion of information and quadratic cost. Uniform or repetitive inputs can cause attention collapse, where all tokens receive similar weights. Mitigations include limiting context windows, adding relative‑position encodings, using sparse or local attention patterns, and applying layer‑norm or dropout to stabilize training.

## Performance & Cost Considerations
Self‑attention scales \(O(n^2 d)\) in time and memory ( *n* = sequence length, *d* = dimension). Track GPU memory usage, FLOPs, and latency per layer. Techniques to reduce overhead: multi‑query attention, low‑rank factorization, or replacing full attention with efficient variants (e.g., Linformer, Performer). Monitoring these metrics helps balance model quality against compute budget.
